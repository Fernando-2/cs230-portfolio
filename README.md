# CS 230 Portfolio Reflection

The Gaming Room was the client for this project. They had an existing Android game called *Draw It or Lose It* and wanted to expand it so it could run on multiple platforms. The goal was to design software that could support more users, teams, and games while keeping the system organized, scalable, and secure.

One thing I think I did well in this documentation was explaining the different operating platforms and comparing their strengths and weaknesses. I also think I did a good job recommending a design approach that made sense for the client’s needs, especially by focusing on a client-server architecture.

Working through the design document helped me because it made me think through the structure of the application before jumping straight into the code. It helped me understand how the different parts of the system should connect, how data should be managed, and why planning matters before development begins.

If I could revise one part of my work, I would improve the evaluation section by adding more specific details about security and scalability. I would make the recommendations more detailed so the client could better understand why one platform or approach would be better than another.

I interpreted the user’s needs by focusing on making the game accessible across different platforms while still keeping the system reliable and easy to maintain. Considering the user’s needs is important because the software has to solve the client’s actual problem, not just function from a technical standpoint. A good design should support both the users and the business goals.

My approach to designing software was to break the system down into smaller parts, look at the requirements, and think about which architecture would best support those needs. In the future, I would use the same strategy by reviewing the client’s goals first, comparing possible solutions, and planning the design before writing the code.
